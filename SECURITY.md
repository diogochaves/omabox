# Security

omabox promises one thing: a box never reaches your real desktop. Its Hyprland does not get your
screen, keyboard or mouse; its apps do not see your HOME, your secrets or your session; and the
commands that drive a box do not land on your desktop instead. This page lists each rule behind that
promise, where omabox (`crates/omabox`, the binary `bin/omabox` is; or a tool) enforces it, and the test in `test/run.sh` that proves it.

## Reporting a problem

Report a way around any rule below privately, through GitHub's
[private vulnerability reporting](https://github.com/diogochaves/omabox/security/advisories/new),
not in a public issue. Say what you ran, what the box reached and your versions (`omabox --version`,
`Hyprland --version`, `omarchy version`). Only the latest release gets fixes.

## What omabox is not

A box is **not a security boundary against a hostile program**. It shares your kernel and your GPU
(a runaway app can load or hang either), and by default your network: it reaches the internet, your
LAN and the servers on your host's loopback (and, through the host's other addresses, any server of yours
listening on all of them), but for the ports you protect (S10). It reads what you mount into it. The rules below keep a
box from reaching your desktop, by mistake or through an app that misbehaves. They are not a defence
against code written to escape. For code you do not trust, use `--net isolated` at least,
[ai-jail](https://github.com/akitaonrails/ai-jail), or a VM.

Commands you run on the host are not boxed either: a project's `sudo ./setup`, or `omabox host --
CMD`, which runs on your real desktop on purpose.

## The rules

A change that weakens a rule updates its row; what no test checks yet is in the issues of the
[Hardening](https://github.com/diogochaves/omabox/milestone/10) milestone.

| Rule | Enforced in | Proven by |
|---|---|---|
| **S1. Hyprland never gets your seat.** Hyprland tries DRM first, so a box gets a GPU render node (`renderD*`, plus NVIDIA's `/dev/nvidia*` nodes for it) and never `/dev/dri/card*`, `/dev/input`, `/run/seatd.sock`, the system bus or your `$XDG_RUNTIME_DIR`. Its runtime dir is one of its own, at the same path. | `up`'s bwrap arguments (a fresh `/dev`, no host `/run`); `render.rs`'s `render_node`/`render_nodes` accept only `/dev/dri/renderD[0-9]+`. By construction: `bwrap.rs`'s `Bwrap` checks every bind's source and destination against the seat's paths and takes devices only as render nodes and NVIDIA's own nodes (`DevNode`, `render.rs`'s `RenderNode`, `NvidiaDev`), the one card path only as the box dir's empty placeholder file; and `up` reads the started box's mountinfo back once its Hyprland is up and ends it if a seat path is there by where it is or by what it is: a mount point that is a seat path, any mount point under the runtime dir's path, a mount whose source (named through omabox's own mountinfo by its device and root) is a seat path or holds one at whatever destination, a card in its `/dev/dri` that is not the empty placeholder, a mounted card or input device by its number; or if its mounts or omabox's cannot be read (`up_box.rs`'s `seat_check`: `seat_mounts`, `dri_seat`, `seat_rdev`), for every box it starts | `t_main`: "no /dev/input", "no DRM card node", "no seatd socket", "no system bus", "the runtime dir is the box's own, not yours"; `t_seat_check` (a mount under a stand-in runtime dir ends the box); `bwrap.rs`'s `no_seat_path_gets_through` (proptest: arbitrary paths at every bind method); `up_box.rs`'s `seat_mounts_finds_the_seat_by_source_and_place` (mountinfo fixtures: `/dev/dri` bound whole, seat paths at other destinations, mounts in the runtime dir), `dri_cards_must_be_placeholders`, `seat_devices_by_number` |
| **S2. The box HOME is fake and holds no secrets.** It starts from `/etc/skel` and gets your Omarchy look (theme, terminal configs, branding, menu extensions) and git's `user.name`/`user.email`. Never `api-keys.env`, keyrings, tokens or the rest of your git config. Links in what it copies stay links, so a link to a secret brings nothing in. Your real HOME is not mounted. A command in a box starts from an empty environment: a host variable goes in only when you name it (`--env`, `--pass`, `--env-file`). | `seed.rs`'s `seed_home`, `seed_copy` and `SEED_ALLOW`, the one list of what of your HOME a box may be seeded from (besides `--seed`, `--desk-shell`'s files and a save), each file of a plugin's settings (`extensions/`) checked for what looks like a key, token or password, as `--desk-shell`'s files are | `t_main`: "real HOME invisible", "no api-keys.env in the box HOME", the whole box HOME read for a file of your secret stores or keyrings and for a key's or a token's shape, a box command's environment for what the caller did not name; `t_unit_seed_copy`; `t_extensions_secret`; `seed.rs`'s tests |
| **S3. Secrets and live sockets are never mounted or copied in.** `--ro-bind`, `--overlay`, `--plugin`, `--theme-dir` and `--seed` refuse anything that is or contains HOME, `~/.config/omarchy` or `/tmp`, anything inside `~/.config/omarchy` but `plugins/` and `themes/` (`api-keys.env`, your hooks), and anything inside or containing `~/.ssh`, `~/.gnupg`, keyrings, `~/.password-store`, `~/.aws`, `~/.kube`, `~/.docker`, `~/.netrc`, git's credential files, gh's, gcloud's, azure's and 1Password's `op` config, omabox's own saves and box HOMEs, the runtime dir, `/run`, `/dev`, `/proc`, `/sys` or `/tmp`'s socket dirs. A path is checked as named and where its links lead, so a link to a secret, or a secret's link to a file elsewhere, is refused too. `--seed` never writes through a link already in the box HOME. Nothing is mounted over the box's own system dirs, runtime dir, `/tmp` or HOME. A refused mount fails before a box dir is made. The repo `up` runs from goes in whole, its `.env` and `.git/config` included; for code you don't trust, use ai-jail, whose hidden paths stay hidden in the box (S9). | `repo.rs`'s `refuse_src`, `upspec.rs`'s `refuse_dest` (`seed_copy` also skips what `refuse_src` refuses); every named mount through `bwrap.rs`'s `user_ro` | `t_unit_mount_rules`, `t_unit_refusals`; `upspec.rs`'s `refuse_dest` proptest |
| **S4. Host code is read-only.** `/usr`, `/etc` and omabox's own files are read-only binds. A repo is mounted read-only at its own path, or, for `omabox run` with no box up, as an overlay whose writes are thrown away. The only writable host folders are the box's own HOME and runtime dir. | `up`'s `--ro-bind` and `--tmp-overlay` arguments: `bwrap.rs`'s `Bwrap`, whose only writable binds are the box's runtime dir, HOME and (`--systemd`) cgroup | `t_main`: "repo read-only"; `t_throwaway`: "host checkout unchanged"; `t_run_options`: an `--overlay` written over (a file changed, removed and renamed, a folder and a link made, a mode changed), each write seen in the box and the host folder as it was; `bwrap.rs`'s `binds` |
| **S5. Each box has its own namespaces and network.** pid, IPC, UTS and network namespaces of its own, so its Xwayland cannot take your X11 socket. A connected box's servers are forwarded to your host's 127.0.0.1 only, never the LAN. An isolated box has a loopback and the `--allow` ports, nothing else. | `up`: bwrap's `--unshare-*`, pasta's arguments: `net.rs`, whose isolated mode carries its allow list | `t_isolated`, `t_connected`, `t_no_new_privs`; `net.rs`'s `pasta_opens_what_it_should` (proptest) |
| **S6. Teardown kills the box and nothing else.** `down` SIGKILLs the box's PID 1, and the kernel ends everything in its pid namespace. A recorded pid counts only while it is still in the box's own pid namespace, and a pasta only while its name and command line are this box's, so a reused pid of yours is never killed. Each process teardown signals (PID 1, pasta and its child, the commands that entered the box, which it continues, its peek windows and the box's reaper; and `save`'s pause of the box's processes, and `stop`'s and `run --replace`'s of a job's) is held by a pidfd opened as it was checked, and signalled through it: one that went in between, its pid reused, gets nothing. A reaper counts only while its command line is this box's reaper's and, for the one the box's folder records, its start time is the recorded one. A job's process counts for `stop` and `--replace` only while it is the box process listed (the box's pid namespace, its pid there, its start time). A box ends with its pasta and with its Hyprland. A box HOME is removed only by its own box's teardown, or once its box is gone in the runtime dir it was made in (its record) and no process has it mounted or open: an omabox with another runtime dir never removes, nor shares, a running box's HOME. | `boxes.rs`'s `box_pid`, `box_pasta`, `pasta_pid`; `down.rs` over `ready.rs`'s `kill_box`, `kill_reapers`, `reaper_of`; `ready.rs`'s `rm_box`, `home_taken`, `sweep_homes` over `homeuse.rs`; `pidfd.rs`'s `Pidfd::pin`; `procfs.rs`'s `entered`; `jobs.rs`'s `pin_in_box` (`save.rs`) and `signal_procs` (`stop`, `--replace`) | `t_main` (down leaves no dir, HOME or reaper), `t_stale_pid`, `t_home_sweep`, `t_isolated_no_pidfile`, `t_pasta_dies`, `t_hyprland_dies`, `t_other_userns`, `t_jobs`, `t_replace`; `ready.rs`'s `kill_box_continues_no_reused_pid` (a stopped process that took an entered one's pid stays stopped) and `kill_reapers_by_their_record` (another ROOT's recorded reaper ended; a record naming another box's reaper, or the wrong start, ends nothing), `down.rs`'s `down_ends_only_a_peek_still_one`, `#[ignore]` tests `t_unit_rust_ignored` runs; the suite's end: no process of any of the run's boxes left (whatever their names, in any runtime dir, under the runner or not), a slow one given a while to end |
| **S7. The tools that drive a box never follow it out.** A box can write its runtime dir and HOME, so omabox runs grim, hyprctl, gdb and its input tools inside the box's namespaces with a clean environment, writes into a box HOME from inside the box (`gdb --watch`'s log, `run -d`'s), and only takes plain names from what the box wrote (no paths), reading its files as regular files only (a FIFO there would hang the host, a link read a host file). omabox's own steps in a box run the system's tools by their full paths with a clean environment (the box's PATH and session environment are the box's to write), and what the host reads of a box's files or a step's answer it bounds on its own side. A command in a box gets only the fds it is given, and its stdin, stdout and stderr reach it as pipes held on the host, or a pseudo-terminal of its own, never a file, a terminal or a device of yours; your terminal is never its controlling terminal (it runs in a session of its own in the box, or has its pseudo-terminal's); a box with no pasta in front of it (a nested one) gets none of its caller's open files. The tools omabox runs in a box's namespaces get the box's 1-byte core limit, so a crash of one makes no notification on your desktop. `omabox env` names the box's own Wayland socket by a hard link in the box's folder, never a path the box can change. | `exec.rs`'s `on_box`, `box_exec`, `stdio_relay`, `box_pty` and `command` (a child entering a box's pid namespace keeps only the fds it is given), `boxes.rs`'s `box_env`, `record_stop.rs`'s `box_copy`, `cmd/gdb.rs`; `up_box.rs`'s launch script (the fds); `enter.rs` (setns through a pidfd of the box's PID 1, the command's own session, no fd of the entry's left to the box) and `cmd/env.rs` | `t_hostile`, `t_gdb`, `t_replace`, `t_jail_record` (a copy out of a box capped), `t_run_stdio`, `t_leak_control` (the nested box), `t_inspect` (the core limit); `env.rs`'s `a_link_in_the_sockets_place_is_refused`; `record_stop.rs`'s `box_copy_is_capped` and `box_copy_bounds_a_fifo` (a file swapped for a FIFO after its stat is read under a time, not for ever: an `#[ignore]` test `t_unit_rust_ignored` runs) |
| **S8. Input never reaches your desktop.** omabox's keyboard, pointer, still and events tools refuse to run outside a box. While the suite runs, a watcher listens to your Hyprland's event socket (read-only): any window, focus change or virtual keyboard of the suite's that shows up there fails the test that was running. At the end it checks your focused workspace and window are what they were. | the tools' own check: `/opt/omabox/share` a mount point and no system bus, as in every box and never on your desktop; the suite's watcher; `up` reaches your Hyprland only through `host.rs`'s `HostSilent`, which starts an interactive box's window `silent`, without focus, and nothing else | `t_unit_pointer`, `t_unit_wait`, `t_unit_inspect` (the refusals); `t_unit_leak_scan`, and `t_leak_control`, which leaks on purpose into a box standing in for your desktop and must see each leak; the suite: your pointer where it was after each box test (read with `hyprctl cursorpos`; a move is noted, since you may be using the mouse, and fails the test under `OMABOX_TEST_CURSOR=strict`) |
| **S9. An agent in ai-jail drives only its own boxes, and gets no more than its jail.** The broker reads the jail's policy from its bwrap command line, which nothing in the jail can change, and refuses what it cannot read. It refuses boxes another jail or you started, folders and a network the jail was not given, a path outside the jail to write a shot to, and `omabox host`. A jail's shots and recordings are written (and a video for a contact sheet read) only through files its own omabox opened and passed: regular files open as they are used, none of the kernel's, never reopened by name. A folder with paths the jail hides goes in with those hidden again, checked on the box's own mounts before anything in it runs. | `broker_side.rs` (the caller's jail and its policy, read from the jail's own bwrap, checked before any command), `select.rs`'s `select_box`, `jailpath.rs`'s `jail_cover` and `jail_verify`, `shots.rs`'s `fd_file`, `relay.rs`; `down.rs` and `up.rs` check a jailed caller's box again once they hold the name's lock | `t_jail`, `t_jail_record`, `t_unit_jail_policy`, `t_unit_jail_covers`, `t_unit_broker_units`, `t_unit_broker_side` (every command a jailed caller is let through or refused, every internal `_` word refused), `t_unit_jailed_caller` (what reaches the relay: values on an fd, never its command line), `t_unit_record`, `t_unit_down_jail_race` |
| **S10. A connected box reaches no protected port.** `protect-ports` in `~/.config/omabox/config` names host ports (none by default) that no connected box reaches: pasta forwards none of them, either way (a box server on one does not take your `127.0.0.1:PORT` while your service there is down), and the box's network namespace rejects a connection to any of the host's own addresses on them, TCP and UDP (a server listening on all addresses is otherwise reached through the host's docker bridge or VPN address). The rule is set by pasta's own shell before anything in the box runs; the box's processes have no capability in that namespace to remove it. An isolated box's `--allow` refuses a protected port. A value that is not a list of ports refuses every `up`, and so does a config that cannot be read. The box's reaper keeps the rule on the host's addresses: one the host gains after the box started is in it within a few tens of milliseconds (the reaper wakes on the kernel's address event), one it loses leaves it (a connection in that moment, or after the reaper is killed, is not covered). | `net.rs`: pasta's `-T`/`-U` and `-t`/`-u` rules with each port left out (`~PORT`), the nftables rule `up_box.rs`'s launch script runs in pasta's shell, its address sets kept by `reap.rs`'s guard (netlink address events, nft in pasta's namespaces through `enter.rs`'s `Entry::pasta`); `up` refuses to start without nft where that script runs it (`/usr/bin`), and a rule nft could not set ends the start | `t_protect_ports` (throwaway servers on 127.0.0.1 and 0.0.0.0, tried by loopback and by each host address; `nft flush ruleset` refused in the box; a box's TCP and UDP servers on a protected port the host does not hold stay off its `127.0.0.1`; a missing and a failing nft, under a stand-in `/usr/bin/nft`); `t_protect_ports_ns` (in a network namespace of the test's own: UDP and TCP, IPv4 and IPv6, to a second link's addresses and over loopback; two addresses gained after up and one lost); `net.rs`'s `pasta_opens_what_it_should` |

The agent guard (`omabox guard`) gives agents' shells a display that does not exist, so a GUI app
an agent starts by mistake fails instead of opening on your desktop (`t_guard`,
`t_unit_guard_settings`, `t_unit_guard_exec_host`). It catches mistakes. It is not a boundary: an
agent can still run anything you could.
